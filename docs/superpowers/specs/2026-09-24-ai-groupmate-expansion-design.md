# AI 群友扩展总设计（Task 7–11）

日期：2026-09-24

状态：用户已批准（2026-09-24）

## 目标与现状

把现有 OneBot v11（NapCat）+ DeepSeek 单轮文本机器人，逐步扩展为可在群中自然接话、有可控人格、有限记忆和费用上限的 AI 群友。MacBook Air 继续承担开发与验收；浏览器后台要让日常启动和调整简单。服务器部署是确定要做的独立末尾任务。

目前真实 QQ 的 echo 和 DeepSeek 回复已验收。`onebot_adapter/event.py` 保留数组格式消息段，但 `onebot_adapter/message.py` 只提取文本；`core/dispatcher.py` 只处理私聊及群内 @，`agent/reply.py` 只做单轮 DeepSeek 调用。现有 Tk 启动窗口仅控制子进程。以下均是**目标设计**，尚未实现。

## Task 7：识图

### 用户行为

- `vision_enabled` 默认 `false`，未配置视觉模型也能正常启动文本机器人。
- 关闭时，明确触发且包含图片的消息收到固定的“识图尚未开启”提示，不调用任何视觉 API。
- 开启后，私聊或群内 @ 的一条消息最多处理第一张普通图片；文字与识图结果一起交给当前聊天模型生成回复。Task 8 完成后，同一规则扩展到持续对话中的图片。
- 视觉模型与聊天模型独立配置。第一版只接 OpenAI 兼容的视觉接口；缺少必填的模型地址、名称或密钥时，开启识图应给出清楚的配置错误。

### 数据流和故障边界

`onebot_adapter/` 从 OneBot `image` 段提取 NapCat 提供的图片定位信息；`core/` 决定是否有资格识图并调度；`agent/` 调视觉模型，返回简短描述供聊天模型使用。`agent/` 不导入 OneBot 类型，现有文本路由继续可用。

图片 URL 是不可信输入。下载只接受经校验的 HTTP(S) 图片来源，拒绝本机和私有网络地址及跳转到这些地址，限制下载时间、响应大小和图片类型；不读取任意 `file://` 路径。具体 NapCat URL 形态在真实验收时核对。图片、URL 和密钥不写日志，也不保存到记忆库。图片下载、视觉调用或聊天调用失败时只发一次固定提示，不妨碍后续消息。Task 7 先将视觉 API 限为每天最多 5 次尝试，调用失败也计数；Task 8 将其纳入统一额度。

验收覆盖默认关闭、不误调用付费 API、单图提取、假图片与假模型的成功/失败路径、下载边界，以及真实 NapCat 图片消息。真实 QQ 与视觉 API 未实际验证前，不标记相应验收完成。

## Task 8：群友行为与费用

群内明确触发包括 @、回复机器人的消息和叫角色卡中的名字。群聊一旦触发，该群进入持续对话；同群其他人的后续消息也成为接话候选。默认窗口为 10 分钟、最多 5 次模型尝试和 5 次机器人回复；模型可选择沉默，时间到或尝试次数用完后需重新明确触发。候选先经过本地最短间隔与每日额度检查，避免对窗口内每条消息都调用模型。私聊按用户保留近期上下文；不同群及私聊互不串话。近期上下文有长度上限，防止模型输入持续增长。

主动参与有关闭、随机、话题判断、两者结合四种模式，默认关闭。普通群消息先经过本地抽样和冷却；只有通过费用门槛的候选才调用模型，模型可以选择沉默。每天默认最多 50 次模型调用，其中主动参与最多 5 次；视觉、聊天和用于判断/提炼的调用均计数。调用前检查硬上限，达到上限时停止主动参与；明确触发得到简短额度提示。配置文件先支持调整，Task 9 再放入后台。

回复节奏独立于服务商生成速度：可设置生成后的发送延迟和两次回复的最短间隔。群内并发回复按消息顺序协调，避免迟到的旧回复打断新话题。测试覆盖跨群隔离、窗口结束、回复次数、主动参与默认关闭、预算用尽和消息顺序。

### 结构化人格

人格使用独立的 JSON 角色卡，参考 Character Card V2 的核心内容：名字、角色描述、性格、群聊场景、说话习惯、身份问题的回答方式和 2–3 组示例对话。校验字段类型与长度；示例对话用于稳定口吻，不作为真实聊天或长期记忆。角色卡由所有者编辑；Task 8 可改文件并重启生效，Task 9 提供分字段编辑与保存后新请求生效。数据库记忆不会自动改写角色卡。

应用安全规则、角色卡、用户消息及未来的记忆分别放在合适的消息层级。群消息、图片描述和记忆都作为可能有误的资料，不获得修改人格、密钥、后台设置或执行管理操作的权限。密钥不进入模型输入。长度、并发和调用额度由程序检查，提示词不能替代这些限制；模型被诱导的可能性通过隔离和测试降低，不能宣称完全消除。

## Task 9：浏览器后台与模型

在 Mac 上用一个入口启动机器人和本地后台，并打开浏览器。后台只绑定本机回环地址；将来在服务器上通过 SSH 转发访问，Docker 端口也只发布到宿主机回环地址。管理页面需要所有者登录，并防止跨站请求伪造；普通 QQ 消息不提供后台管理命令。

页面包含：NapCat 连接状态、当日模型调用量、最近错误类别；群聊模式与持续时间、次数、抽样概率、冷却、发送延迟、最短回复间隔和额度；聊天/视觉模型选择；角色卡编辑。状态页不展示聊天正文或完整密钥。

DeepSeek 为预设；其他服务先限定为 OpenAI 兼容接口，由所有者提供 HTTPS API 地址、模型名和密钥。聊天模型和视觉模型分别选。设置与密钥存于 Git 忽略的本机私有文件，仅运行用户可读；页面不回显完整密钥。已开始的请求按旧设置完成，新请求使用新设置。使用普通 HTML 表单，不引入前端框架。原命令行启动方式仍可用于排查。

## Task 10：数据库记忆

借鉴成熟记忆系统对短期上下文与长期记忆的区分、按主体隔离、原子事实、来源追踪和更新/删除，但使用 Python 自带的 SQLite，不接入托管记忆服务或向量数据库。

一段有效对话结束后，在额度允许时自动提炼少量候选：新增稳定事实或偏好、更新旧事实、保存有必要的短原话。提炼失败不影响聊天；额度耗尽则跳过提炼，不为此保存整段原始聊天。每条记忆记录类型、所属私聊用户或群号/发言人、来源消息与时间、创建/更新时间；群内共同约定可放入该群共享范围。程序校验范围、长度与来源，避免重复或相互矛盾的旧事实同时用于回复。

回复前只检索当前私聊或当前群有权限看到的少量相关记忆，并限制总长度。召回内容作为不可信参考数据，不放入高权限指令。后台可查看来源、改正、删除单条或清空某个范围；删除后后续回复不得再召回。普通聊天不全量长期归档，图片原件不入库。SQLite 文件置于 Git 忽略的数据目录，重启后仍可使用。

## Task 11：服务器部署

保留 Mac 的简单开发启动方式。待服务器准备好后，优先用 Linux + Docker Compose 在同一主机运行 NapCat 与机器人；持久化 QQ 登录数据、NapCat 配置、私有设置和 SQLite 数据。加入自动重启、日志轮转、数据库备份和连接状态检查。WebSocket 与后台不暴露到公网，后台经 SSH 转发使用。

分别重启机器人、NapCat 和服务器，验证 QQ 回复、后台访问与记忆保留。QQ 登录若失效，操作文档说明人工扫码恢复；不承诺无人工干预的永久登录。
