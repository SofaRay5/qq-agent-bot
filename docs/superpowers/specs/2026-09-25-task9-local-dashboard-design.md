# Task 9 本地浏览器后台与模型切换设计

**日期：** 2026-09-25

**状态：** 已获用户批准（2026-09-25）

**依据：** [AI 群友扩展总设计](2026-09-24-ai-groupmate-expansion-design.md)

## 1. 目标与成功标准

Task 9 为 Mac 本地运行增加一个简单的浏览器后台。后台先启动，用户登录后再手动启动或停止机器人。它统一管理 NapCat、聊天模型、识图模型、Task 8 行为设置和人格文件，并展示有限的运行状态。

完成标准：

- 一条命令启动仅监听 `127.0.0.1` 的后台并打开浏览器。
- 首次使用可创建长期管理密码，之后必须登录才能查看或修改后台。
- 后台可启动、停止机器人，且不会产生重复实例。
- 后台可安全保存 NapCat Token、聊天 API Key 和识图 API Key，不回显完整密钥。
- 行为、人格和模型修改经校验后对后续新消息生效；已开始的请求按旧配置完成。
- NapCat 地址或 Token 修改后明确提示重新启动机器人。
- 页面可查看连接状态、当日调用量和少量安全错误类别，不展示聊天正文。
- 现有命令行入口和 Tkinter 启动方式继续可用。

## 2. 范围边界

本 Task 包含本地单所有者后台、机器人生命周期控制、现有配置编辑、聊天与识图模型切换、状态和安全错误摘要。

本 Task 不包含长期记忆管理、公网或局域网访问、Docker、服务器守护、浏览器完整日志、聊天记录、多用户权限、前端框架、插件系统和服务端实时推送。Task 10 负责长期记忆，Task 11 负责服务器部署。

Task 7 的真实图片验收仍可能受 NapCat RKey 服务影响；该外部问题不阻塞本 Task，但后台应将图片获取失败显示为安全错误类别。

## 3. 总体架构

新增本地管理入口，例如：

```bash
bash scripts/start_dashboard.sh
```

入口启动一个轻量异步 HTTP 服务，绑定固定回环地址并打开默认浏览器。Web 服务与机器人共享一个 Python 进程和一个 `asyncio` 事件循环。登录后台后机器人保持停止，直到用户点击“启动机器人”。

使用 `aiohttp` 作为唯一新增的直接依赖。页面由服务端生成普通 HTML/CSS，交互使用普通表单和少量浏览器原生能力，不引入前端框架或构建工具。

从 `main.py` 提取可启动、可停止的机器人运行单元。命令行入口继续调用同一运行单元；后台通过进程内运行管理器创建或关闭机器人任务。关闭后台进程时先正常停止机器人。

运行管理器串行处理启动和停止请求，并持有当前运行状态。它不实现通用任务系统、进程通信层或插件接口。

## 4. 本机认证与安全

后台只有一个所有者账号，不建立用户表或权限角色。

- 首次启动且不存在认证文件时，只允许在回环地址创建管理密码。
- 密码使用 Python 标准库 `hashlib.scrypt` 和随机盐保存为哈希，不保存明文。
- 登录成功后创建随机会话；Cookie 设置 `HttpOnly`、`SameSite=Strict`，仅 HTTPS 时才设置 `Secure`。本地 HTTP 不伪造 `Secure` 保证。
- 所有修改和控制请求必须同时通过登录与 CSRF Token 校验。
- 连续登录失败增加短暂延迟，并对单进程内连续尝试作有限限制。
- 服务固定绑定 `127.0.0.1`，不提供页面配置监听地址。
- 忘记密码时关闭后台并删除本机认证文件，再次启动后重新创建；不实现邮件和安全问题找回。

认证数据、NapCat Token 和 API Key 存入 Git 忽略的本机私有文件。创建或替换文件后将权限限制为当前用户读写。页面只显示“已配置”及可选的末尾少量字符；密钥输入留空表示保持原值，只有明确的清除操作才删除密钥。

状态、页面、错误摘要和日志不得包含聊天正文、图片地址、完整密钥、完整模型响应或私有配置路径。

## 5. 页面与功能

后台使用四个简单的服务端页面。

### 5.1 状态与控制

显示机器人状态：未启动、启动中、已连接、重连中和已停止。提供启动、停止按钮。配置缺失或校验失败时禁用启动，并指出无效字段。

显示当日总调用、主动调用、识图调用及各自剩余额度。显示最近约 20 条安全错误类别及时间，例如认证失败、模型超时、NapCat 断线和图片获取失败。错误摘要只保存在内存，后台重启后清空。

页面用简单定时刷新获取新状态，不加入服务端 WebSocket 或前端状态框架。

### 5.2 行为设置

编辑 Task 8 已有字段：

- 主动模式和随机概率；
- 持续对话窗口、最大尝试和最大回复次数；
- 最短回复间隔和发送延迟；
- 上下文消息数和字符数；
- 每日总调用、主动调用和识图调用额度。

后台直接复用 `Settings` 的字段和 Pydantic 校验，不复制另一套数值范围。

### 5.3 模型与连接

分别配置：

- NapCat WebSocket 地址与 Token；
- 聊天模型的服务预设、HTTPS API 地址、模型名和 API Key；
- 识图开关，以及识图模型的服务预设、HTTPS API 地址、模型名和 API Key。

DeepSeek 作为预设；其他服务限定为 OpenAI 兼容接口。聊天和识图模型相互独立。外部模型地址必须使用 HTTPS，不接受 URL 中的用户名、密码、查询参数或片段。本机 NapCat 可使用根路径 `ws://127.0.0.1`，并继续接受合法的 `wss://` 地址。

### 5.4 人格

分字段编辑现有角色卡：名字、描述、性格、场景、说话风格、身份回答及最多三组示例对话。后台复用 `Persona` 的字段、长度限制和整卡校验，不允许普通 QQ 消息修改人格。

## 6. 配置存储与运行时更新

现有 `config/settings.json` 和 `config/persona.json` 继续作为行为与人格的唯一持久化来源。后台认证、连接和密钥使用单独的 Git 忽略私有文件。命令行入口继续支持现有环境变量，后台入口从私有文件装配同一机器人运行单元。

配置提交按以下顺序执行：

1. 验证登录与 CSRF Token；
2. 合并“保持原密钥”等表单语义；
3. 使用现有或新增的严格 Pydantic 模型完整校验；
4. 在同目录写入临时文件，设置私有权限后用 `os.replace` 原子替换；
5. 成功后替换运行时不可变配置快照。

任一步失败都保留原文件和原运行时配置，并向页面返回不含敏感值的字段错误。

每条新消息开始处理时取得一次配置快照，并在该次处理期间保持引用。因此已开始的请求使用旧快照完成，后续消息使用新快照。行为、人格或模型切换不得清空进程内短期对话上下文。NapCat 地址和 Token 属于连接级配置，只在下一次机器人启动时应用。

## 7. 状态和错误数据流

OneBot 客户端向运行管理器报告连接成功、断开和重连状态。运行管理器报告启动中、运行中、停止中和已停止。状态变更只暴露枚举值和时间，不暴露事件内容。

`DailyBudget` 增加只读的当日计数能力，继续使用现有 `data/model_usage.db`，不创建第二个统计数据库。

应用在内存中维护固定长度的安全错误摘要。错误在写入前映射为预定义类别；未知错误只记录异常类名，不保存异常文本。完整调试信息继续输出到本机终端，并遵守现有秘密和消息内容限制。

## 8. 失败处理

- 后台无法启动时，在终端输出简短错误类别并退出。
- 机器人配置无效时，后台继续运行，机器人保持停止。
- 重复点击启动或停止时，运行管理器返回当前状态，不创建第二个任务。
- NapCat 或模型临时失败时，机器人继续按现有规则处理后续消息，并更新安全状态。
- 配置文件写入失败时不更新运行时快照。
- 后台请求异常时返回通用错误页面，不把堆栈、文件路径或秘密发送给浏览器。
- 浏览器关闭不停止机器人；终端 `Ctrl+C` 同时正常关闭机器人和后台。

## 9. 验证策略

开发期间只运行与当前改动相关的测试。Task 结束时运行一次完整 `uv run pre-commit run --all-files` 和 `git diff --check`。

自动化测试覆盖：

- 首次创建密码、正确和错误登录、退出及会话失效；
- 未登录或缺少 CSRF Token 时不能修改配置或控制机器人；
- 密码使用哈希保存，密钥不回显，状态和错误不泄漏敏感值；
- 配置完整校验、原子保存、留空保持密钥和明确清除；
- 启动、停止、重复请求和后台退出清理；
- 旧请求使用旧快照，新请求使用新快照，短期上下文不因更新清空；
- 假 NapCat 下从后台启动到机器人处理消息的闭环。

真实 Mac 验收步骤：

1. 一条命令打开后台；
2. 首次创建长期管理密码并重新登录；
3. 保存 NapCat、聊天模型和可选识图模型配置；
4. 点击启动并在真实 QQ 中完成文字回复；
5. 修改回复速度或人格，确认下一条消息使用新配置；
6. 停止并重新启动机器人；
7. 核对连接状态、额度和安全错误类别；
8. 核对页面不显示完整密钥和聊天正文。

Task 7 的真实识图通过条件仍以 NapCat 能提供可读取图片及视觉模型成功响应为准，不因后台能保存识图配置而自动通过。
