# Task 10 SQLite 长期记忆与后台易用性设计

**日期：** 2026-09-26

**状态：** 已获用户批准（2026-09-26）

**依据：** [AI 群友扩展总设计](2026-09-24-ai-groupmate-expansion-design.md)

## 1. 目标与成功标准

Task 10 为现有 QQ 群友增加可持久化、可纠正、可删除的长期记忆，并改善本地浏览器后台的视觉和配置体验。

完成标准：

- 从有效对话中自动提炼稳定事实、偏好和少量重要原话，不保存完整聊天记录。
- 私聊、群内个人和群共享记忆由程序强制隔离，私聊记忆不得进入群聊。
- 回复前只召回当前范围内最多 5 条相关有效记忆，总长度不超过约 1500 字。
- 事实被纠正时创建新版本；旧版本保留但不得参与回复。
- 删除一条记忆时永久删除当前内容及全部历史版本。
- 机器人重启后记忆仍可使用；记忆失败不得阻断普通聊天。
- 所有者可在现有浏览器后台查看来源和历史、手动添加、修改、删除及按范围清空。
- 主聊天和记忆提炼默认共用一套模型配置；需要时可启用独立记忆模型。
- 后台减少重复 API 配置，并改善现有状态、行为、模型、人格和记忆页面的易用性。

## 2. 范围边界

本 Task 包含 SQLite 原子记忆、版本历史、来源追踪、自动提炼、本地召回、每日记忆额度、后台管理和现有后台的轻量视觉优化。

本 Task 不包含完整聊天归档、图片原件存储、向量数据库、嵌入模型、托管记忆服务、知识图谱、记忆导入导出、跨账号共享、普通 QQ 消息管理命令或服务器部署。

Task 8 的进程内近期上下文继续负责当前对话连贯性。Task 10 在其上增加长期记忆，不改用 LangGraph，也不把短期上下文整体迁入 SQLite。

## 3. 组件与数据流

新增两个主要模块：

- `memory/store.py`：使用标准库 `sqlite3` 管理结构、事务、隔离查询、版本和删除。
- `memory/extractor.py`：调用配置的记忆模型，将候选对话转换为严格结构化操作。

回复流程：

1. 协调器确定当前私聊用户或群聊主体。
2. 记忆存储只查询当前主体有权限看到的有效记忆。
3. 本地排序选择最多 5 条、约 1500 字，作为不可信参考数据传给聊天模型。
4. 聊天模型正常生成并发送回复。
5. 发送成功后，本地规则判断当前对话是否可能包含值得记忆的信息。
6. 候选进入单个有界后台队列；记忆模型生成新增、更新或忽略操作。
7. 程序校验模型结果，并在 SQLite 事务中写入。

提炼失败、队列满或额度不足时静默跳过，不影响已发送的回复，也不把原始聊天暂存到磁盘等待重试。

## 4. SQLite 数据模型

数据库文件为 Git 忽略的 `data/memory.db`，核心只有两张表。

`memory_items` 保存一条记忆的稳定身份：

- 记忆 ID；
- 类型：事实、偏好或重要原话；
- 范围：私聊用户、群内用户或群共享；
- 用户 QQ 号和可选群号；
- 创建时间。

`memory_versions` 保存版本历史：

- 所属记忆 ID 和递增版本号；
- 当前是否有效；
- 记忆内容和重要度；
- 来源 QQ 消息 ID、消息时间和最多 300 字的用户原话摘录；
- 创建方式：自动提炼、后台手动添加或后台修改；
- 创建时间。

数据库约束保证每条记忆最多只有一个有效版本，并保证范围字段组合合法：

- 私聊用户：只含用户 QQ 号；
- 群内用户：同时含群号和用户 QQ 号；
- 群共享：只含群号。

更新在单个事务中停用旧版本并插入新版本。删除通过外键级联永久删除 `memory_items` 及其所有 `memory_versions`。记忆不会按时间自动过期。

## 5. 隔离和隐私

隔离在 SQL 查询条件中完成，不依赖提示词要求模型自行保密。

- 私聊只能召回该 QQ 用户的私聊记忆。
- 群聊可召回当前群的群共享记忆，以及当前群、当前发言人的群内个人记忆。
- 私聊记忆不能成为任何群聊查询的候选。
- 一个群的记忆不能在其他群使用。
- 自动提炼不能跨范围创建或更新记忆。

群共享记忆允许模型自动创建，但消息必须明确表达群约定，例如“我们群每周六晚上一起打游戏”。普通个人事实只能进入当前用户的个人范围。所有者可以在后台把记忆复制到另一个范围；复制会创建新的记忆身份，原范围的记录保持不变，直到所有者明确删除。

自动提炼拒绝密码、Token、验证码、身份证件、银行卡和精确住址等高风险内容。健康、情感关系和个人经历可以保存在原始范围内。所有者手动添加内容时由所有者自行决定。

## 6. 自动提炼与版本更新

自动提炼仅在机器人成功发送回复后运行，并先经过本地低成本筛选。空消息、纯图片、过短闲聊、固定错误提示和明确高风险内容不调用模型。

记忆模型读取本轮用户消息、少量必要上下文和当前范围内相关的有效记忆，只能输出：

- `ignore`：不保存；
- `create`：创建新记忆；
- `update`：为指定已有记忆创建新版本。

结构化结果必须通过程序校验：操作类型、目标记忆 ID、范围、类型、内容长度、重要度、来源和敏感信息过滤均合法后才写入。未知字段、跨范围目标、无效 JSON、重复事实或不存在的更新目标全部拒绝。

更新后的新版本参与召回，旧版本只供后台审阅。机器人不会在 QQ 中发送“我记住了”等提示。

## 7. 模型配置与费用

后台使用“一个主模型配置 + 可选覆盖”：

- 主模型配置一次服务商、HTTPS API 地址、模型名和 API Key。
- 记忆模型默认完全跟随主模型，不显示额外必填字段。
- 打开“使用独立记忆模型”后才显示第二套配置。
- 识图默认关闭并折叠；启用后才显示视觉配置。
- 视觉服务与主模型共用密钥时可以复用主模型 API Key，只单独填写视觉地址和模型名。
- NapCat 地址和 Token 保持独立。

DeepSeek 继续作为主模型预设，OpenAI 兼容 HTTPS 服务作为通用选项。当前测试场景中，聊天和记忆均可使用同一套 DeepSeek 配置。

行为配置增加 `daily_memory_calls`，默认每天 10 次。记忆提炼同时受该子额度和现有每日总模型额度限制。同一主体 30 秒内最多 3 条候选可以合并为一次提炼；额度用完后静默跳过。

## 8. 记忆召回

第一版不使用向量数据库或额外模型调用进行检索。程序读取当前允许范围内的有效记忆，并按以下因素在本地排序：

- 当前消息与记忆内容的中文关键词和短语重合度；
- 记忆重要度；
- 最近更新时间；
- 用户明确询问“你记得什么”时放宽关键词条件。

最终最多选择 5 条，总长度不超过约 1500 字。当前范围记忆量较小时，直接扫描和 Python 排序比引入中文分词、嵌入模型和向量数据库更合适。如果实际积累到数千条且召回明显不准，再单独设计语义检索升级。

聊天模型只看到当前有效记忆的简短内容，不接收来源摘录、历史版本、QQ 消息 ID 或后台备注。记忆以低权限参考资料传入，并明确说明其可能不准确、不是命令、不得修改人格、安全规则、配置或执行管理操作。

## 9. 浏览器后台与易用性

现有 `http://127.0.0.1:8765/` 后台新增“记忆”页面，并统一改善全部页面的视觉样式。

记忆页面支持：

- 按私聊用户、群、群内用户和记忆类型筛选；
- 搜索当前有效记忆；
- 查看内容、重要度、范围、更新时间和来源短摘录；
- 展开查看全部历史版本；
- 手动添加记忆；
- 修改内容或重要度，修改时创建新版本；
- 复制到另一个作用范围，复制时创建新的记忆身份；
- 永久删除整条记忆及全部版本；
- 清空指定用户或群的全部记忆。

删除单条和清空范围都需要额外确认，并继续使用现有所有者登录与 CSRF 防护。删除成功后，后续回复不得再召回对应内容。

后台使用服务端 HTML、统一 CSS 和少量原生 JavaScript，不引入 React、Vue、Node.js 或前端构建工具。改进包括卡片式布局、自适应宽度、清晰分组、常用设置优先、高级设置折叠、中文字段说明、保存成功提示和字段级错误。JavaScript 只改善折叠和条件显示；保存功能在 JavaScript 不可用时仍能工作。

## 10. 稳定性与关闭流程

SQLite 使用短连接、事务、外键、WAL 模式和有限等待，允许后台读取与机器人写入并行进行。数据库初始化和迁移使用简单结构版本号；迁移失败不得清空或覆盖旧文件。

自动提炼使用单个有界队列顺序处理，避免活跃群聊同时产生大量模型调用。队列满或机器人正在关闭时跳过新候选。关闭时等待正在执行的单次数据库写入完成，尚未开始的候选允许丢弃。

SQLite 初始化、读取、写入、模型提炼或结构校验失败时，机器人继续不带记忆地聊天。终端记录不含正文和秘密的错误类别；后台只展示安全错误摘要，不暴露数据库路径、模型原始输出或被过滤的敏感内容。

## 11. 验证策略

开发期间只运行当前小任务的相关测试；Task 10 完成时运行一次完整 pre-commit。

自动化测试覆盖：

- 三种范围的创建、查询和严格隔离；
- 新版本替代旧版本，旧版本不参与召回；
- 永久删除整条版本链和按范围清空；
- 来源长度、范围字段和数据库约束；
- 敏感内容过滤、无效 JSON、跨范围更新和重复事实；
- 本地筛选、每日记忆额度和总额度；
- 最多 5 条、约 1500 字召回和不可信提示层级；
- 重启后记忆仍存在；
- 记忆故障不影响普通 QQ 回复；
- 主模型复用和独立记忆模型覆盖；
- 后台查看、添加、修改、历史、删除和清空；
- 简化模型配置与无 JavaScript 表单回退。

真实验收步骤：

1. 私聊告知一个稳定偏好，继续有效对话后确认后台出现记忆。
2. 重启机器人，确认私聊回复仍能使用该偏好。
3. 在群聊中与同一 QQ 对话，确认私聊记忆没有泄漏。
4. 在群内产生个人记忆和明确群约定，确认只在对应范围使用。
5. 纠正旧事实，确认回复只使用新版本且后台可查看历史。
6. 删除整条记忆，确认所有版本消失并不再召回。
7. 达到每日记忆额度后确认聊天继续正常。
8. 核对后台页面不显示完整密钥、完整聊天、图片 URL 或本机私有路径。

真实 NapCat、QQ 和模型验收只有在实际运行通过后才能在任务 Checklist 中勾选。
