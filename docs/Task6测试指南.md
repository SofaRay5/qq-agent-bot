# Task 6 测试指南

目标：保留 Task 6 当时的 DeepSeek 基础闭环验收步骤。当前群友行为请使用 [Task 8 测试指南](Task8测试指南.md)。

## 1. 准备

确认以下条件都满足：

- NapCat 已登录机器人 QQ。
- NapCat「网络配置」中的 WebSocket 服务端已启用。
- 地址为 `ws://127.0.0.1:3001/`；如果你改过端口，测试时填写实际地址。
- 消息格式为 `array`。
- 你知道 NapCat WebSocket Token。它不是 WebUI 登录密钥。
- 你有可用且有余额的 DeepSeek API Key。真实回复会产生少量 API 费用。

不要把 Token 或 API Key 写进文档、截图、聊天消息或 Git。

## 2. 先运行自动化测试

在项目根目录打开终端：

```bash
uv sync
uv run pytest
uv run pre-commit run --all-files
```

三个命令都应成功。自动化测试会使用假 NapCat 和假 LLM，不会调用付费 API；它同时检查模型超时或空回复后发送固定提示，并能继续处理下一条消息。

## 3. 打开启动窗口

```bash
uv run python scripts/start_ui.py
```

窗口中填写：

1. `WebSocket 地址`：默认是 `ws://127.0.0.1:3001/`。
2. `NapCat Token`：NapCat WebSocket 服务端配置中的 Token。
3. `DeepSeek API Key`：你的 DeepSeek API Key。
4. 点击“启动”。

看到“进程运行中；请在 QQ 中验证连接”只代表机器人进程已启动。是否真正连接成功，需要继续发送 QQ 消息验证。启动后两个密钥框会被清空，也不会保存密钥。

## 4. 测试私聊回复

使用另一个 QQ 号私聊机器人，发送：

```text
请只回复：Task 6 私聊成功
```

通过标准：机器人在 QQ 中返回模型生成的文字，而不是把你的原消息原样复制回来。模型措辞可能略有不同。

## 5. 测试群聊规则

在机器人所在的群中依次测试：

1. 不 @ 机器人，发送 `这条不应回复`。机器人不应回复。
2. @ 机器人并发送 `请只回复：Task 6 群聊成功`。机器人应返回模型生成的文字。

## 6. 检查单轮限制

连续发送：

```text
请记住数字 7319
```

然后发送：

```text
我刚才让你记住的数字是什么？
```

当前版本没有对话记忆，因此第二条回复不保证知道 `7319`。这是预期行为，不算失败。

## 7. 停止机器人

点击窗口中的“停止”，状态应变成“已停止”。再次发送 QQ 消息，机器人不应回复。也可以直接关闭窗口，窗口会先停止机器人进程。

## 8. 验收记录

完成后记录结果，不要记录任何密钥：

- [x] 自动化测试通过。
- [x] 私聊收到模型生成的回复。
- [x] 群聊未 @ 时不回复。
- [x] 群聊 @ 后收到模型生成的回复。
- [x] 点击“停止”后机器人不再回复。

验收日期：2026-09-24。用户确认以上项目均无问题，Task 6 的真实服务验收完成。

## 常见问题

- 收到“暂时无法回复，请稍后再试”：查看启动 UI 的终端输出，只提供错误类型，不要复制密钥。常见原因是 API Key 无效、账户余额不足、网络不可用或模型调用超时。
- 一直没有回复：确认 NapCat 已登录、WebSocket 服务端已启用、端口与地址一致、Token 正确，并确认测试消息来自另一个 QQ 号。
- 群聊不回复：必须先 @ 机器人，再输入文字。
- 窗口显示进程已退出：查看启动窗口所用终端中的错误信息。
